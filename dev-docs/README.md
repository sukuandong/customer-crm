# dev-docs — 开发协作文档

这里放**给团队和 AI 看的开发过程文档**，与面向使用者的 `docs/`（会被同步到公开 Wiki）分开。

```
dev-docs/
├── specs/   # Dev Spec：每个功能的需求、设计、验收标准
└── adr/     # ADR：架构决策记录（为什么这么选）
```

## 什么时候写

| 情况 | 写什么 |
|---|---|
| 新增功能、改动现有功能行为 | 从 `specs/_TEMPLATE.md` 复制一份，命名 `<序号>-<功能名>.md` |
| 技术选型、架构调整、重要权衡 | 从 `adr/_TEMPLATE.md` 复制一份，命名 `<四位序号>-<决策名>.md` |
| 只是修 bug / 改文案 | 不用写 Spec，但要在 `STATUS.md` 的"最近变更"记一行 |

## 工作流

1. 动手前：写 Spec / ADR（可以很短，5～10 行也行）
2. 改代码中：按 `AGENTS.md` 的分层约定修改
3. 提交前：更新 `STATUS.md`（进度）和 `CHANGELOG.md`（对外变更）
4. 提交信息写清背景，例如：`feat(customers): 列表支持状态批量筛选`

## 给 AI 的提示

打开本仓库的 AI 助手应按此顺序读取上下文：
`AGENTS.md` → `STATUS.md` → `CHANGELOG.md` → `dev-docs/adr/` → 相关 Spec → 代码。
不要只看代码就动手改，先确认"当前进度"和"已有决策"，避免推翻之前的选择。
